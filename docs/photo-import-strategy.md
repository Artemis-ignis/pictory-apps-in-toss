# 픽토리 사진 가져오기 정책

## 확인한 앱인토스 제약

- `fetchAlbumItems`는 `types`, `maxCount`, `maxWidth`, `base64`만 지원한다.
- `fetchAlbumPhotos`는 `maxCount`, `maxWidth`, `base64`만 지원한다.
- 공식 SDK 타입과 문서 기준으로 최신순, 오래된 순, 날짜 범위, 앨범명, 인스타그램 전용 필터 파라미터는 없다.
- 사진첩 사용에는 `granite.config.ts`의 `permissions: [{ name: "photos", access: "read" }]` 설정이 필요하며 현재 픽토리에 적용되어 있다.
- `fetchAlbumItems`는 토스앱 5.261.0 이상이 필요하다.

## 픽토리 구현 기준

- 기본 가져오기: `최신순`
- 오래된 사진 정리: EXIF 촬영일, 앱인토스 ID 날짜 추정값, 파일 수정일 순으로 만든 `createdAt` 기준 오름차순 정렬
- 날짜 정리: EXIF 촬영일, 앱인토스 ID 날짜 추정값, 파일 수정일 순으로 만든 `createdAt`이 선택 날짜와 같은 항목만 사용
- 인스타 업로드용: 이미지 신호가 있는 경우 피드 허용 비율인 4:5~1.91:1 후보만 사용
- 네이티브 앱인토스 응답이 촬영일 메타데이터를 직접 주지 않으므로 base64 이미지 안의 EXIF 날짜를 먼저 읽고, 없으면 ID에 포함된 날짜를 추정하고, 그래도 없으면 현재 시각을 쓴다.
- 자동 가져오기에서 최신순이 아닌 `오래된순`, `날짜`, `인스타` 모드는 플랜 분석 한도보다 넓은 후보 창을 먼저 가져온 뒤 내부 필터/정렬을 적용하고, 실제 분석은 다시 플랜 한도까지만 자른다.
- 후보 창은 메모리와 WebView 안정성을 위해 최대 300장으로 제한한다. 앱인토스 SDK가 전체 앨범 날짜 검색을 제공하지 않으므로, 이 기능은 “가져온 후보 안에서의 날짜/비율 필터”로 표현한다.
- 사진 권한이 거부된 경우에는 토스 앱 권한에서 사진 접근을 허용하라는 문구를 별도로 보여준다.
- 권한은 허용됐지만 SDK 호출이나 토스 앱 버전 문제로 실패한 경우에는 토스 앱 버전이나 사진첩 상태를 확인하라는 문구를 보여준다.

## 남은 실기기 확인

- 실제 토스앱 `fetchAlbumPhotos` 반환 순서가 최신순인지 확인해야 한다.
- 실제 토스앱에서 반환되는 base64 이미지 데이터에 촬영일/EXIF가 보존되는지 확인해야 한다.
- OS 기본 앨범 선택 UI에서 다중 선택 UX가 충분한지 실기기로 확인해야 한다.
